# 전주 NaVi 시연 직전 개발 계획

작성일: 2026-09-19. 이 문서는 개발 계획이며 아래의 신규 PoC 초기 정렬이나 검증이 완료됐다는 뜻은 아니다.

## 목표와 확정 범위

추가 촬영이나 학습용 영상 제출 없이 기존 5개 수집 자료를 사용한다. 휴대폰의 현재 카메라에서 콘을 검출하고, 고정된 전주 PoC 코스에서 경로 방해 여부에 따라 우회 경로·AR 띠·음성 안내를 함께 갱신하는 앱을 준비한다.

- 정밀 경사·굴곡 추종은 제외하고 현재 수평면 기반 AR 띠를 사용한다.
- 대상은 경로 안의 정지 콘, 경로 밖의 같은 종류 콘, 지나가는 사람이다.
- 사용자는 지정 출발점에서 안내된 방향으로 휴대폰을 향하고 시작을 한 번 누른다. 실행 중 사례 선택이나 우회 실행 버튼은 요구하지 않는 것을 목표로 한다.
- 자유로운 출발 위치, 임의 장소 탐색, 일반 목적의 정밀 위치 추정은 이번 범위가 아니다.
- 시작 위치·방향 맞추기와 최종 현장 실행 확인은 추가 데이터 촬영과 구분한다. 코드 개발만으로 현장 성공을 검증했다고 표시하지 않는다.

## 출발 상태

콘 규칙 검출기, 기존 공간 판단 연결, Live 준비 화면의 검출 표시가 구현돼 있다. 기존 2,946장 입력에서 129개 프레임에 143개 후보 박스가 나왔다. 이 수치는 정확도가 아니다. 앱·AI·Fusion 테스트 71개와 APK 빌드는 통과했다.

현재 Live 시작은 정확한 두 기준점을 요구한다. 원본 5개 수집본에는 검증된 지도 정합이 없으므로 이 요구를 그대로 필수로 두는 것은 추가 촬영 없는 고정 코스 시연 준비와 맞지 않는다. 첫 단계에서 아래의 별도 PoC 초기 정렬을 구현한다. 기존 GPS 오차를 축소하거나 정밀 정합으로 위장하는 방식은 사용하지 않는다.

## 1. 고정 코스와 PoC 초기 정렬

기존 영상의 출발·분기·복귀 장면과 AR 이동 기록을 현재 고정된 8개 지도 구간에 대조한다. 촬영한 우회 구간과 지도에 등록된 대체 경로가 대응하는지 확인하고 출발 사진, 진행 방향, 기본 경로, 우회 경로, 장애물 개입 구간을 시연 설정으로 묶는다. 대응이 불명확한 구간은 확정 경로로 승격하지 않고 검토 결과를 남긴다.

신규 PoC 모드는 지정 출발점에서 시작할 때의 AR 위치를 상대 좌표 원점으로 놓고, 사용자가 맞춘 정면을 지정 코스의 진행 방향과 연결한다. 경로를 이 상대 공간에 배치하고 이후 이동은 AR 추적을 이용한다. 실측 좌표 두 점을 입력하는 현재 정밀 모드는 유지하되 PoC 모드의 시작 전제조건으로 사용하지 않는다.

초기 정렬의 출처는 사용자 출발점·방향 설정으로 기록하고 측정된 지도 정확도와 구분한다. 계약·로그·서버 정책도 이 차이를 표현하도록 변경한다. `0.5m` 같은 검증되지 않은 정확도를 채우거나 `contract_test` 입력을 실시간 근거로 보내지 않는다. 추적 손실·세션 재시작·진행 구간 모호성에는 경로 안내를 보류하고 초기 정렬 복구를 안내한다.

완료 기준: 기준점 좌표 입력 없이 고정 코스 모드를 시작할 수 있고, 출발 방향에 따른 경로 좌표 변환과 추적 손실 처리가 테스트된다. 출발 사진·방향·경로 설정이 준비된다. 실제 길과 겹치는 정도는 최종 현장 확인 항목으로 남긴다.

## 2. 기존 자료로 콘 검출과 사례 검증

기존 자료에서 콘 장면과 비콘 장면을 다시 선별한다. 현재 색·띠·형태 규칙의 누락과 오검출을 검토하고 필요 시 개선한다. 장면 라벨에는 원본 파일, 프레임, 시각, 검토 출처와 미검수 여부를 남긴다. 조정에 사용한 구간과 회귀 확인 구간을 구분하며 근접 프레임 반복을 독립 평가처럼 계산하지 않는다.

세 가지 사례의 기대 동작은 다음과 같다.

| 사례 | 기대 동작 |
|---|---|
| 경로 안의 정지 콘 | 깊이와 상대 위치, 지속 관측, 진행 구간 조건이 충족되면 우회 판단으로 전달 |
| 경로 밖의 콘 | 검출 박스는 표시하되 경로 변경은 발생하지 않음 |
| 지나가는 사람 | 일시적인 통과로 불필요한 우회를 발생시키지 않음. 계속 정지해 경로를 점유하면 별도로 지속성 판단 |

화면 중앙에 콘이 있다는 이유만으로 차단으로 처리하지 않는다. 현재 영상 검출은 AR 깊이·추적 정보와 연결한다. 원래의 보도 마스크 검사는 기존 녹화에서 유효한지 확인하며, 자료가 부족한 경우 차단·비차단 성공으로 계산하지 않고 판단 보류 원인을 기록한다.

완료 기준: 확인 가능한 기존 장면에 대한 검출·추적·판단 로그가 나온다. 필요한 실제 사례가 자료에서 확인되지 않으면 그 항목은 미검증으로 남기고, 별도 합성 공간 입력으로 로직을 검사한다. 합성 결과를 현장 사례 성공으로 합산하지 않는다.

## 3. 우회·AR·음성의 전체 흐름 연결

AI는 이미지와 공간 관측을 출력하고, 경로 계층이 현재 진행 구간과 영향을 받는 구간을 결정한다. PoC 모드에서는 초기 정렬에 따른 상대 경로와 실제 깊이 관측을 사용하고, 진행 구간을 유일하게 판단할 수 있을 때만 시연 세션의 우회를 요청한다. 공동 Graph의 검증 상태나 접근성 속성은 바꾸지 않는다.

기존 고정 경로 범위 안에서 우회 경로를 계산하고 같은 경로 버전으로 2D 지도, AR 띠, 남은 거리, 음성 안내를 갱신한다. 같은 콘의 반복 관측이 중복 우회를 일으키지 않게 하고, 예전 서버 응답이 새 경로를 덮지 않게 한다. AR 띠는 현재 수평면 렌더링을 유지한다.

완료 기준: 실제 이미지 검출과 개발용 공간 입력을 구분한 통합 검사에서 세 사례의 기대 동작, 중복 억제, 최신 경로 반영이 확인된다. 정밀 정합용 기존 모드의 규칙을 PoC 모드 변경이 우회하지 않는다.

## 4. 시작 한 번으로 진행되는 시연 화면

출발점 사진과 바라볼 방향을 제공하고, 시작 전에 카메라·AR 추적·바닥 인식·필요 공간 입력·한국어 음성·서버 상태를 자동 점검한다. 준비 상태와 사용자가 지금 할 행동을 짧게 표시한다. 실행 중에는 걷기, 잠시 멈추기, 우회 방향, 도착만 안내한다.

서버 단절, 깊이 부족, 위치 추적 손실, 우회 경로 없음은 각각 구분하여 표시하고 로그를 저장한다. 근거 없는 경로를 계속 표시하거나 오류를 성공으로 처리하지 않는다. 도착·중단 시 로그는 자동 저장한다. 준비 화면과 시연 안내에는 구현 세부사항을 불필요하게 노출하지 않는다.

완료 기준: 정상 시나리오는 시작 이후 사례/장애물/우회 버튼 조작 없이 완료된다. 오류 상태에서 사용자가 할 다음 행동이 표시된다.

## 5. 설치·네트워크·회귀 검증

기존 프레임의 새 검출 실행, 공간 판단 단위 검사, 경로 API 통합 검사, Android 테스트와 lint, APK 빌드를 수행한다. 실제 녹화 기반 검사와 합성 계약 검사를 따로 보고한다. 감지부터 우회 응답·화면 갱신까지 시간을 측정하고 지연이 발생한 단계를 기록한다.

S23에 연결할 수 있을 때 해당 기기만 대상으로 설치하고 카메라, 화면 회전, 음성, 재시작, 로그 저장을 점검한다. USB 포트 포워딩에 의존하지 않는 인터넷 연결도 확인한다. 인터넷 주소가 임시 터널이면 그 수명과 서버 PC 실행 의존성을 설치 안내에 명시하며 영구 서버처럼 설명하지 않는다. 추가 촬영 자료 제출은 요구하지 않는다.

완료 기준: APK와 검증 보고서, 시작 위치 안내, 시연 순서가 준비된다. 설치·기기 검사는 실제 연결 및 수행 여부대로 별도 표시한다. 기기가 없는 동안 빌드 성공을 설치 성공으로 보고하지 않는다.

## 시연 직전에 남는 사용자 행동

필요 시 APK 설치를 위한 기기 연결, 지정 출발점으로 이동, 안내 방향으로 휴대폰 맞추기, 시작 버튼 한 번 누르기, 안내에 따라 걷기다. 시연 전 현장에서 AR 띠가 진행 방향과 맞는지 짧게 확인한다. 현장 대응 확인이 실패하면 정렬을 다시 맞추며 검증되지 않은 안내를 계속하지 않는다.

## 진행 순서와 완료 보고

1단계의 경로 대응·상대 정렬 계약을 먼저 확정한다. 그다음 2단계 검출 검증, 3단계 통합, 4단계 화면, 5단계 설치 검증 순서로 진행한다. 기존 검출과 렌더러를 재사용한다. 정밀 지형 처리나 범용 위치 추정으로 범위를 넓히지 않는다.

각 단계는 변경 파일, 실제 수행한 검사, 미검증 항목으로 보고한다. 최종 보고는 개발 완료, 기존 자료 검증, 기기 확인, 현장 확인을 나눠 작성한다. 현재 단계에서는 현장 성공이나 소요 시간을 확정하지 않는다. 가장 큰 불확실성인 1단계를 마친 뒤 남은 작업량을 다시 산정한다.
