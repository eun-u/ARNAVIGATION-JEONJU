# 전주 해커톤 지정 경로 모드

사용자가 마지막 촬영 파일과 지도에 지정한 동선을 반영한다. 도착점은 사용자가 확인한 **아래쪽 합류점**이다. 새 촬영은 요구하지 않는다.

## 기존 경로와의 차이

기존 8개 구간 제한에는 동쪽 곡선 보행로 `OSM_E_1327522116_93e880e796`이 빠져 있었다. 이 구간은 기존 Graph에 이미 존재하는 약 104.5m의 `footway`다. 마지막 파일 `NaVi-collect-20260919-024719-670-dd86e6fb`의 후반 이동과 대응한다. 원시 GPS 대조는 위치 정확도 검증으로 간주하지 않는다.

새 앱 기본 진입 모드 `Hackathon`은 별도 내장 설정 `jeonju_hackathon_course.json`을 사용한다. 공용 Graph와 기존 서버 8개 구간 설정은 변경하지 않는다.

- 출발: 위도 35.8463514, 경도 127.1319861.
- 시작 방향: 남쪽 보행로, 위도 35.8458917, 경도 127.1319832 방향.
- 장애물 앞에서 현재 위치로부터 이미 걸어온 보행로를 역방향으로 따라 출발점 쪽으로 돌아간다.
- 위쪽 연결부에서 동쪽 보행로로 진입하고 곡선 보행로를 따라 남쪽으로 내려간다.
- 도착: 위도 35.8457996, 경도 127.1319938의 합류점. 기존 서쪽 목적지까지 이어가지 않는다.

## 고정한 것과 실제 입력

경로 선택, 장애물 구역, 도착점은 사용자 지정값이다. 카메라 영상, 콘 인식, AR 이동 추적, 현재 위치에 따른 되돌아가는 경로 시작점은 실제 입력을 사용한다. 콘의 3D 위치나 통행 차단 여부를 자동 판단했다고 기록하지 않는다.

지정 장애물 구역의 접근 보행로에서 실제 콘 인식이 일정 시간 이어지면 지정 경로로 전환한다. 다른 위치, 가장자리 콘, 사람 검출은 이 전환 신호로 사용하지 않는다. 인식이 어려울 때는 **장애물 확인 · 지정 우회 시작** 버튼을 제공한다. 두 방식은 화면과 로그에 `cone_cue` / `operator_button`으로 구분한다. 수동 전환도 AR 추적과 현재 위치를 요구한다.

내장 경로·모델·약도를 사용하므로 이 모드의 안내/전환에는 서버나 지도 타일 다운로드가 필요 없다. ARCore와 한국어 음성 데이터는 기기에 준비되어 있어야 한다. 기존 서버 502 문제를 이 모드의 준비 조건에서 제외하며, 서버 자체를 복구했다고 주장하지 않는다.

## AR과 기록

실제 PoC AR 렌더러를 약 2m 간격의 파란 바닥 화살표로 변경했다. 화살표는 각 경로 구간의 진행 방향을 따른다. 수평 바닥 높이를 사용하며 경사·굴곡의 정밀 추종은 하지 않는다. 합성 이미지가 앱 실행 검증을 대신하지 않는다.

시작 위치·방향을 사용자가 맞추는 상대 AR 방식이다. 절대 위치 정확도와 접근성은 미검증 상태로 유지한다. 추적이 끊기면 안내를 종료하고 출발점에서 다시 준비한다. 도착은 실제 상대 위치 관측으로 판단하며 타이머로 도착을 만들지 않는다.

이벤트와 요약에는 `input_mode=Hackathon`, `route_source=user_declared_fixed_course`, `server_used=false`, `autonomous_obstacle_localization=false`를 기록한다. 영상은 실제 ARCore 카메라 기록이며 고정 경로 출처는 별도 메타데이터다. 원본 5개 파일은 수정하지 않는다.

## 시연 순서

1. 출발점에서 남쪽 보행로를 향하고, 앞쪽 바닥이 보이도록 기기를 든다.
2. 바닥·AR 추적·한국어 음성 준비 후 **시연 시작**을 누른다.
3. 장애물 앞에서 멈춰 콘을 비춘다. 자동 전환이 되지 않으면 지정 우회 버튼을 누른다.
4. 음성에 따라 뒤돌아가고, 위쪽 연결부에서 화살표가 안내하는 동쪽 보행로로 이동한다.
5. 아래 합류점 도착 시 안내가 종료되고 기록이 저장된다.

실기기 설치와 현장 전체 흐름의 성공 여부는 실제 검사 결과와 별도로 남긴다. 테스트 통과와 빌드만으로 현장 성공을 확정하지 않는다.

## 이번 검사와 설치 파일

- Android 단위 검사 총 127개 중 125개 통과, 명시적 입력 경로가 필요한 녹화 진단 2개 건너뜀.
- 에뮬레이터 실제 모델/내장 코스 준비 및 기록 어댑터 검사 10개 통과. 준비 검사에는 연결 불가능한 서버 주소를 넣었다.
- 첫 실제 준비 검사에서 MediaPipe 이미지 해제 후 같은 비트맵을 콘 탐지에 읽던 오류를 발견했다. 해제 전에 픽셀과 크기를 확보하도록 수정한 뒤 통과했다.
- Debug/Benchmark/AndroidTest APK 빌드 및 Debug lint 통과.
- 물리 S23은 연결되어 있지 않아 최신 APK 설치와 실제 AR 현장 실행은 미수행.

설치 파일: `artifacts/jeonju/runs/hackathon-east-delivery-20260919/NaVi-Jeonju-Hackathon.apk`.
해시와 상세 결과: 같은 폴더의 `verification.json`.

## 객체 표시와 촬영 화면 문구 수정

실시간 카메라와 영상 재생의 탐지 표시에 객체 이름·탐지 점수 배지를 추가했다. 콘은 주황색, 사람은 하늘색, 차량은 보라색, 자전거는 초록색으로 구분하며 실제 검출 박스만 그린다. 라이브 화면은 기존 ARCore 회전·화면 크롭 변환을 유지한다. 점수는 탐지기의 출력값이며 정확도나 통행 차단 확률이 아니다. 나무 분류는 현재 탐지 모델에 없다. 시작 전 미리보기는 기존처럼 콘만 탐지하고, 시작 후에는 전체 객체 탐지 결과를 표시한다.

사용자 요청에 따라 상단의 `해커톤 지정 코스 · 서버 없이 안내` 문구와 `인식이 어려우면 아래 버튼을 누르세요.` 문장을 삭제했다. 수동 우회 버튼과 전환 출처 기록은 유지한다.

수정 APK: `artifacts/jeonju/runs/hackathon-overlay-delivery-20260919/NaVi-Jeonju-Hackathon.apk`.
이번 수정의 검사 결과와 해시는 같은 폴더의 `verification.json`에 별도로 기록한다. 앞 절의 전체 검사 결과는 이전 경로 버전에 대한 기록이다.
